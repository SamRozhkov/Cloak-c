# libcloak-common: ClientHello Templates Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and unit-test `cloak_clienthello_build` — splicing Cloak's own protocol data (random/session_id/X25519 key share) into byte-exact, real-browser-captured TLS ClientHello templates for Chrome, Firefox, and Safari, including variable-length SNI (server name) rewriting.

**Architecture:** A new pair of files in the existing `libcloak-common` library: `cloak/clienthello.h` (an offset-table struct plus `cloak_clienthello_build`) and `src/clienthello.c` (the three static byte-array templates plus the splice/patch logic). No new CMake target — `clienthello.c` is added to the existing `cloak-common` static library, and its tests to the existing `libcloak-common/tests`. This module produces only the Handshake-message bytes of a ClientHello (`handshake_type(1) + length(3) + body`) — the 5-byte TLS record-layer wrapper is a separate, trivial concern left to whichever future module actually sends bytes on a socket (the client transport plan), matching how Go Cloak's own `internal/client/TLS.go` builds the handshake body and record-wraps it as two distinct steps.

**Tech Stack:** C11, CMake, the existing custom assert-based test framework (`libcloak-common/tests/test_framework.h`, reused).

## Provenance of the template data (read before touching anything)

The three byte arrays embedded in Task 1 and Task 2 below are not hand-written or guessed. They were generated by a throwaway Go program using `github.com/refraction-networking/utls` v1.8.0 — the exact same library, and exact same version, that Go Cloak's own `internal/client/TLS.go` depends on for this purpose — calling the identical sequence Go Cloak's `buildClientHello` uses (`utls.UClient(...)`, `BuildHandshakeState()`, `SetClientRandom()`, overwrite the X25519 entry in the `KeyShareExtension`, `BuildHandshakeState()` again, read `HandshakeState.Hello.Raw`), for `utls.HelloChrome_Auto`, `utls.HelloFirefox_Auto`, and `utls.HelloSafari_Auto`.

To find the exact byte offsets without hand-counting TLS wire format (error-prone and exactly the kind of mistake that would silently corrupt every ClientHello this project ever sends), the generator used two independent, cross-checked techniques:
1. **Marker search**: the random/session_id/key_share fields were set to distinctive, non-repeating byte patterns (`0x00..0x1F`, `0x40..0x5F`, `0x80..0x9F` respectively) before marshaling, then located by searching the output for each unique pattern.
2. **Structural parse**: a from-scratch TLS ClientHello walker (handshake header → client_version → random → session_id → cipher_suites → compression_methods → extensions, descending into `server_name` and `key_share` extensions specifically) computed the same offsets independently by parsing the wire structure.

Both techniques agreed exactly, for all three browsers — this cross-validation is the evidence the offsets below are correct, the same rigor used for the verified Salsa20 test vectors in an earlier plan. A separate experiment (holding one `uclient`'s extension order fixed and mutating only the `SNIExtension.ServerName` field between two `BuildHandshakeState()` calls, to avoid uTLS's own extension-order randomization contaminating the comparison) empirically derived the SNI variable-length patching model in Global Constraints below, rather than working it out from memory of the TLS extension spec.

**Maintenance note** (documented, not solved by this plan, per spec §5): when browsers change their TLS fingerprint, these templates must be regenerated the same way — a throwaway Go program using an updated uTLS, not by hand-editing the byte arrays.

## Global Constraints

- Language: C11 (`-Wall -Wextra` clean build, enforced project-wide).
- Platform: Linux only (per spec §2), though nothing in this module is Linux-specific (pure C11, no syscalls) — build/test through Docker anyway for process consistency:
  ```bash
  docker build -q -f Dockerfile.dev -t cloak-c-dev .
  docker run --rm -v "$(pwd)":/src -w /src cloak-c-dev bash -c "cmake -S . -B build && cmake --build build && ctest --test-dir build --output-on-failure"
  ```
- No wire compatibility with Go Cloak is required (per spec §1) — but the byte-level ClientHello *content* is captured directly from the same uTLS library Go Cloak uses, so it is in fact byte-identical to what a real Chrome/Firefox/Safari (as uTLS models them) would send, which is the actual DPI-evasion goal.
- **Template scope**: each template is the ClientHello **handshake message only** (`handshake_type(1) + length(3) + body`), with no TLS record-layer wrapper (`content_type + version + record_length`). Adding the 5-byte record layer is out of scope for this plan.
- **Baked-in placeholder SNI**: every template was captured with server name `"www.example.com"` (15 bytes). `cloak_clienthello_build` always replaces this with the caller's real server name.
- **SNI variable-length patching model** (empirically derived, see Provenance above): changing the SNI hostname from length `sni_host_len` (the template's baked-in 15) to a new length `host_len` (`delta = host_len - sni_host_len`, which may be negative) requires:
  1. Shifting every byte at or after `sni_host_off` (i.e. `memmove`-ing the template's suffix, starting right after the old hostname, to start right after the new hostname).
  2. `handshake_length` — the 3-byte big-endian field at byte offset `[1:4)` — `+= delta`.
  3. `extensions_length` — a 2-byte big-endian field, offset given per-template below — `+= delta`.
  4. `sni_ext_length` — the `server_name` extension's own 2-byte big-endian length field — `+= delta`.
  5. `sni_list_length` — the `server_name_list`'s 2-byte big-endian length field (nested one level inside the extension) — `+= delta`.
  6. `host_name_length` — the 2-byte big-endian field immediately before the hostname bytes — is **set directly** to `host_len` (not incremented).
  All five of `random_off`, `session_id_off`, `extensions_length_off`, `sni_ext_length_off`, `sni_list_length_off`, `sni_host_length_off` sit **before** `sni_host_off` in every one of the three captured templates, so their own byte *positions* are unaffected by the shift — only the *values* at `extensions_length_off`/`sni_ext_length_off`/`sni_list_length_off`/`sni_host_length_off` change. `keyshare_off`, by contrast, sits **after** `sni_host_off` in all three templates (the `key_share` extension is captured after `server_name` in each), so the X25519 key share must be spliced at `keyshare_off + delta` in the output buffer, not at the raw template offset.
- Testing: reuse `libcloak-common/tests/test_framework.h` — no new test framework.
- Build: CMake. `clienthello.c` added to the existing `cloak-common` target; `test_clienthello` added to the existing `libcloak-common/tests` CMakeLists.

```c
#ifndef CLOAK_CLIENTHELLO_H
#define CLOAK_CLIENTHELLO_H

#include <stddef.h>
#include <stdint.h>

/* Describes a captured, byte-exact browser ClientHello (handshake message
 * only, no TLS record layer) and the byte offsets within it where Cloak's
 * own protocol data gets spliced in, or where the placeholder SNI hostname
 * lives. See the plan's Global Constraints for the exact patching model
 * cloak_clienthello_build implements. */
typedef struct {
    const uint8_t *bytes;
    size_t len;

    size_t random_off;             /* 32 bytes */
    size_t session_id_off;         /* 32 bytes */
    size_t keyshare_off;           /* 32 bytes: the X25519 sub-share inside the key_share extension */

    size_t extensions_length_off;  /* 2-byte big-endian */
    size_t sni_ext_length_off;     /* 2-byte big-endian */
    size_t sni_list_length_off;    /* 2-byte big-endian */
    size_t sni_host_length_off;    /* 2-byte big-endian */
    size_t sni_host_off;
    size_t sni_host_len;           /* length of the baked-in placeholder hostname */
} cloak_clienthello_template_t;

extern const cloak_clienthello_template_t cloak_clienthello_chrome;

/* Builds a ClientHello handshake message (no TLS record layer) from tmpl:
 * splices random/session_id/x25519_key_share (each exactly 32 bytes) into
 * their template-defined positions, and replaces the template's baked-in
 * placeholder SNI hostname with server_name. server_name may be a
 * different length than the template's placeholder, in which case every
 * length field the SNI change affects, and every byte after the hostname,
 * is patched/shifted accordingly.
 *
 * server_name must be non-empty, NUL-terminated, and at most 253 bytes
 * (the DNS hostname length limit).
 *
 * Returns the number of bytes written to out (> 0) on success, or -1 on
 * failure (server_name empty or too long, or out_cap too small for the
 * result). */
long cloak_clienthello_build(const cloak_clienthello_template_t *tmpl,
                              const uint8_t random[32],
                              const uint8_t session_id[32],
                              const uint8_t x25519_key_share[32],
                              const char *server_name,
                              uint8_t *out, size_t out_cap);

#endif
```

Create `libcloak-common/tests/test_clienthello.c`:

```c
#include "cloak/clienthello.h"
#include "cloak/common.h"
#include "test_framework.h"

#include <string.h>

/* Minimal from-scratch structural walk of a built ClientHello, independent
 * of clienthello.c's own logic, used only to verify structural integrity
 * (extensions_length actually equals the sum of the extensions that
 * follow, and the server_name extension's own nested lengths are
 * internally consistent). Mirrors the exact walk used to derive the
 * offsets in the first place (see the plan's Provenance section). */
typedef struct {
    int ok;
    size_t sni_host_off;
    size_t sni_host_len;
    size_t extensions_length_off;
    size_t sni_ext_length_off;
    size_t sni_list_length_off;
    size_t sni_host_length_off;
} walk_result_t;

static uint16_t read_be16(const uint8_t *p) {
    return (uint16_t)((p[0] << 8) | p[1]);
}

static walk_result_t walk_and_verify(const uint8_t *buf, size_t len) {
    walk_result_t r;
    memset(&r, 0, sizeof(r));

    if (len < 4) {
        return r;
    }
    size_t hs_len = ((size_t)buf[1] << 16) | ((size_t)buf[2] << 8) | buf[3];
    if (hs_len != len - 4) {
        return r; /* handshake_length must equal everything after the 4-byte header */
    }

    size_t off = 4;
    off += 2; /* client_version */
    off += 32; /* random */
    if (off >= len) return r;
    size_t sid_len = buf[off];
    off += 1 + sid_len;
    if (off + 2 > len) return r;
    size_t cs_len = read_be16(buf + off);
    off += 2 + cs_len;
    if (off >= len) return r;
    size_t cm_len = buf[off];
    off += 1 + cm_len;
    if (off + 2 > len) return r;

    r.extensions_length_off = off;
    size_t ext_len = read_be16(buf + off);
    off += 2;
    size_t ext_end = off + ext_len;
    if (ext_end != len) {
        return r; /* extensions_length must account for exactly the rest of the buffer */
    }

    while (off < ext_end) {
        if (off + 4 > ext_end) return r;
        uint16_t ext_type = read_be16(buf + off);
        uint16_t ext_data_len = read_be16(buf + off + 2);
        if (off + 4 + ext_data_len > ext_end) return r;

        if (ext_type == 0x0000) { /* server_name */
            r.sni_ext_length_off = off + 2;
            size_t data_off = off + 4;
            if (data_off + 5 > ext_end) return r;
            size_t list_len = read_be16(buf + data_off);
            r.sni_list_length_off = data_off;
            uint8_t name_type = buf[data_off + 2];
            size_t host_len = read_be16(buf + data_off + 3);
            r.sni_host_length_off = data_off + 3;
            r.sni_host_off = data_off + 5;
            r.sni_host_len = host_len;
            if (name_type != 0x00) return r;
            if (list_len != 3 + host_len) return r; /* name_type(1) + host_name_length(2) + hostname */
            if (data_off + 5 + host_len > ext_end) return r;
        }

        off += 4 + ext_data_len;
    }

    r.ok = 1;
    return r;
}

static void fill_marker(uint8_t *buf, uint8_t seed) {
    for (int i = 0; i < 32; i++) {
        buf[i] = (uint8_t)(seed + i);
    }
}

static void test_build_chrome_round_trip_and_structural_integrity(void) {
    uint8_t random[32];
    uint8_t session_id[32];
    uint8_t key_share[32];
    fill_marker(random, 0x10);
    fill_marker(session_id, 0x30);
    fill_marker(key_share, 0x50);

    uint8_t out[2048];
    long n = cloak_clienthello_build(&cloak_clienthello_chrome, random, session_id, key_share,
                                      "www.example.com", out, sizeof(out));
    ASSERT_TRUE(n > 0);
    ASSERT_EQ_INT(n, (long)cloak_clienthello_chrome.len); /* same-length SNI: total length unchanged */

    ASSERT_MEM_EQ(out + cloak_clienthello_chrome.random_off, random, 32);
    ASSERT_MEM_EQ(out + cloak_clienthello_chrome.session_id_off, session_id, 32);
    ASSERT_MEM_EQ(out + cloak_clienthello_chrome.keyshare_off, key_share, 32);
    ASSERT_MEM_EQ(out + cloak_clienthello_chrome.sni_host_off, "www.example.com", 16); /* incl. NUL, harmless */

    walk_result_t w = walk_and_verify(out, (size_t)n);
    ASSERT_TRUE(w.ok);
    ASSERT_EQ_INT(w.sni_host_off, cloak_clienthello_chrome.sni_host_off);
    ASSERT_EQ_INT(w.sni_host_len, 16); /* strlen("www.example.com") */
}

static void test_build_shorter_sni_shrinks_and_shifts_keyshare(void) {
    uint8_t random[32];
    uint8_t session_id[32];
    uint8_t key_share[32];
    fill_marker(random, 0x10);
    fill_marker(session_id, 0x30);
    fill_marker(key_share, 0x50);

    const char *short_name = "a.co"; /* 4 bytes, vs. the 15-byte placeholder -- delta = -11 */
    long expected_delta = (long)4 - (long)cloak_clienthello_chrome.sni_host_len;

    uint8_t out[2048];
    long n = cloak_clienthello_build(&cloak_clienthello_chrome, random, session_id, key_share,
                                      short_name, out, sizeof(out));
    ASSERT_TRUE(n > 0);
    ASSERT_EQ_INT(n, (long)cloak_clienthello_chrome.len + expected_delta);

    /* The key share must have moved: it sits after the SNI in every
     * supported template, so its position in the output is
     * keyshare_off + delta, NOT the raw template offset. This is the
     * direct regression test for the delta-adjustment logic. */
    long shifted_keyshare_off = (long)cloak_clienthello_chrome.keyshare_off + expected_delta;
    ASSERT_MEM_EQ(out + shifted_keyshare_off, key_share, 32);

    walk_result_t w = walk_and_verify(out, (size_t)n);
    ASSERT_TRUE(w.ok);
    ASSERT_EQ_INT(w.sni_host_len, 4);
    ASSERT_MEM_EQ(out + w.sni_host_off, short_name, 4);
}

static void test_build_longer_sni_grows_and_shifts_keyshare(void) {
    uint8_t random[32];
    uint8_t session_id[32];
    uint8_t key_share[32];
    fill_marker(random, 0x10);
    fill_marker(session_id, 0x30);
    fill_marker(key_share, 0x50);

    const char *long_name = "a-considerably-longer-hostname.example.com"; /* 43 bytes */
    long expected_delta = (long)43 - (long)cloak_clienthello_chrome.sni_host_len;

    uint8_t out[2048];
    long n = cloak_clienthello_build(&cloak_clienthello_chrome, random, session_id, key_share,
                                      long_name, out, sizeof(out));
    ASSERT_TRUE(n > 0);
    ASSERT_EQ_INT(n, (long)cloak_clienthello_chrome.len + expected_delta);

    long shifted_keyshare_off = (long)cloak_clienthello_chrome.keyshare_off + expected_delta;
    ASSERT_MEM_EQ(out + shifted_keyshare_off, key_share, 32);

    walk_result_t w = walk_and_verify(out, (size_t)n);
    ASSERT_TRUE(w.ok);
    ASSERT_EQ_INT(w.sni_host_len, 43);

}

static void test_build_rejects_empty_server_name(void) {
    uint8_t random[32] = {0};
    uint8_t session_id[32] = {0};

static void test_build_rejects_server_name_too_long(void) {

    char too_long[255];
    memset(too_long, 'a', sizeof(too_long) - 1);
    too_long[sizeof(too_long) - 1] = '\0'; /* 254 chars, exceeds the 253-byte DNS limit */

    long n = cloak_clienthello_build(&cloak_clienthello_chrome, random, session_id, key_share,
                                      too_long, out, sizeof(out));
    ASSERT_EQ_INT(n, -1);
}

static void test_build_rejects_buffer_too_small(void) {
    uint8_t random[32] = {0};
    uint8_t session_id[32] = {0};
    uint8_t key_share[32] = {0};
    uint8_t out[10]; /* far smaller than any real template */

    long n = cloak_clienthello_build(&cloak_clienthello_chrome, random, session_id, key_share,
                                      "www.example.com", out, sizeof(out));
    ASSERT_EQ_INT(n, -1);
}
```

```c
static void patch_be16_delta(uint8_t *p, long delta) {
    long v = ((long)p[0] << 8) | (long)p[1];
    v += delta;
    p[0] = (uint8_t)(v >> 8);
    p[1] = (uint8_t)v;
}

static void store_be16(uint8_t *p, uint16_t v) {
    p[0] = (uint8_t)(v >> 8);
    p[1] = (uint8_t)v;
}

long cloak_clienthello_build(const cloak_clienthello_template_t *tmpl,
                              const uint8_t random[32],
                              const uint8_t session_id[32],
                              const uint8_t x25519_key_share[32],
                              const char *server_name,
                              uint8_t *out, size_t out_cap) {
    size_t host_len = strlen(server_name);
    if (host_len == 0 || host_len > 253) {
        return -1;
    }

    long delta = (long)host_len - (long)tmpl->sni_host_len;
    long new_len = (long)tmpl->len + delta;
    if (new_len < 0 || out_cap < (size_t)new_len) {
        return -1;
    }

    /* Unchanged prefix: everything up to (not including) the old hostname. */
    memcpy(out, tmpl->bytes, tmpl->sni_host_off);
    /* The new hostname. */
    memcpy(out + tmpl->sni_host_off, server_name, host_len);
    /* Unchanged suffix: everything after the old hostname, shifted by delta. */
    size_t old_suffix_off = tmpl->sni_host_off + tmpl->sni_host_len;
    size_t suffix_len = tmpl->len - old_suffix_off;
    memcpy(out + tmpl->sni_host_off + host_len, tmpl->bytes + old_suffix_off, suffix_len);

    /* Patch the length fields the SNI change affects. All of these sit
     * strictly before sni_host_off in every supported template, so their
     * own byte positions are unaffected by the shift -- only the values
     * they hold change. */
    long hs_len = ((long)out[1] << 16) | ((long)out[2] << 8) | out[3];
    hs_len += delta;
    out[1] = (uint8_t)(hs_len >> 16);
    out[2] = (uint8_t)(hs_len >> 8);
    out[3] = (uint8_t)hs_len;

    patch_be16_delta(out + tmpl->extensions_length_off, delta);
    patch_be16_delta(out + tmpl->sni_ext_length_off, delta);
    patch_be16_delta(out + tmpl->sni_list_length_off, delta);
    store_be16(out + tmpl->sni_host_length_off, (uint16_t)host_len);

    /* Splice in Cloak's own protocol data. random_off/session_id_off are
     * always before sni_host_off (fixed ClientHello prefix layout shared
     * by every template), so their positions are unaffected by the shift.
     * keyshare_off is after sni_host_off in every supported template, so
     * it must be adjusted by delta. */
    memcpy(out + tmpl->random_off, random, 32);
    memcpy(out + tmpl->session_id_off, session_id, 32);
    memcpy(out + (size_t)((long)tmpl->keyshare_off + delta), x25519_key_share, 32);

    return new_len;
}
```

## What comes after this plan

This plan builds only the client-side template infrastructure. Per the design spec's module breakdown, the next plans in dependency order are:

1. **`libcloak-server`: ClientHello parsing** — a minimal, defensive parser (spec §5's other half, mirroring Go's `internal/server/TLSAux.go`) that extracts `random`/`session_id`/SNI/`key_share` from an arbitrary, potentially-adversarial incoming ClientHello — a meaningfully different task from this plan's fixed-template splicing, since the server cannot assume any particular extension ordering or count. Deliberately scoped as its own plan rather than folded into this one.
2. **`libcloak-mux`: session/stream/switchboard** — multiplexing (spec §6), using the reactor and frame codec already built.
3. **`libcloak-client`**: connector, direct transport — the first real consumer of `cloak_clienthello_build`, wrapping its output in the 5-byte TLS record layer (out of this plan's scope, per Global Constraints) and sending it over a `cloak_reactor_t`-managed socket. Also where `ServerName: random` domain generation (mentioned in spec §5) belongs — it's a caller-side concern, not a template-module concern.
4. **`libcloak-server`**: dispatcher state machine, auth, redirect-on-fail, SQLite user manager, admin API.
5. **`cmd/ck-server`, `cmd/ck-client`**: CLI binaries.

- **Provenance discipline:** every numeric offset and every byte in the three templates traces back to a real run of a real, currently-used TLS-fingerprinting library (uTLS v1.8.0), cross-validated by two independent derivation methods, not transcribed from memory or invented. The SNI-patching field model (which fields shift, by how much, in what order) was derived the same way — by diffing two real uTLS-produced ClientHellos with the extension order held fixed — not reconstructed from memory of the TLS 1.3 spec.
